规范写在 AI 规范 里，是用来说明「该怎么做」的； 这一页是用来验证「有没有做到」的。它逐条对照同一份规则集并给出行号与修法—— AI 写完自己跑一遍，比人肉 review 有效。

17 条规则 纯前端 · 不外传 Ctrl/⌘ + Enter 运行
Check

粘贴检查

可以贴一个组件片段，也可以贴整页 HTML。内容不会离开这台机器——检查全部在浏览器里完成，没有网络请求。

Rules

检查项清单

错误会让功能不工作或主题失效；提醒是可维护性问题，可以权衡后再决定改不改。 这份清单与检查实现读的是同一份规则表，不会出现「页面写着会查、实际没查」。

Limits

它能查出什么，查不出什么

说清边界，免得把「检查通过」误当成「已经正确」。

查得出
  • 用了别的库的类名、Token、字号、间距、圆角
  • 弹层触发按钮漏了 data-target
  • 弹层、图标按钮、折叠面板、标签页缺 ARIA
  • 按钮漏写 type、错误态没告知读屏
  • !important 与自写固定定位弹层
查不出
  • 对比度是否达标 —— 要算实际渲染色，属于运行时
  • 键盘顺序与焦点陷阱是否真的可用
  • 命中的 data-target 是否真的存在对应元素
  • 文案是否说清了结果与下一步
  • 写在外部 CSS 文件里的样式（这里只扫 HTML 内的内联样式与 class）
后面这几项要靠人工与真实的键盘、读屏测试。工具的边界说清楚，比含糊地说「已检查」有用。
规则集来自哪里：docs/oneui.spec.js 里的禁止清单与状态契约。 改了规范，这一页的规则与文案跟着变——页面里没有手写的第二份副本。
